# 300_実装 — CC実施要領

工程定義表全体は [WORKFLOW.md](../../WORKFLOW.md) を参照。本ファイルは 300_実装 工程における CC（Claude Code）自身の実施要領のみを扱う。

## INPUT

- CA からの実装プロンプト
- 関連する `docs/internal-design/*.md`（自動ロードされないため、CC 自身が対象領域を判断し明示的に読む）

## 実施方針

1. 既存パターン踏襲を優先する。新しい抽象化・独自の保存 UI・独自の state 管理パターンを安易に導入しない（`CLAUDE.md`「設計原則ダイジェスト」節・各 `docs/internal-design/*.md` を参照）
2. 実装に着手する前に、変更対象領域に対応する `docs/internal-design/*.md` のポインタ先を確認し、過去の却下パターン・構造的な弱点の記録を踏まえる
3. 設計案に明記されていない実装ディテールで判断に迷った箇所は、実装を止めずに自分の判断で進めつつ、必ず報告に含める（何を、なぜその判断にしたか）
4. ビルド確認は `cargo build` / `tsc --noEmit` まで。`npm run tauri dev` の起動・GUI 動作確認は行わない（`CLAUDE.md`「テストに関する制約」節）

## OUTPUT

- 実装済みコード
- ビルド結果報告（判断に迷った点を含む）
