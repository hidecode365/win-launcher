# 500_リリース前作業 — AD実施要領

工程定義表全体は `WORKFLOW.md` を参照。本ファイルは 500_リリース前作業 工程における AD（アプリ開発担当）自身の実施要領のみを扱う。

## INPUT

- MG からのドキュメント反映依頼

## 手順

1. `DESIGN_LOG.md` の該当トピックの結論を、`AGENTS.md`「設計原則ダイジェスト」節（再利用可能な原則のみ）と対応する `docs/internal-design/*.md`（現状仕様・経緯）へ正式反映する。その際、型・仕様が実装と一致しているか、DESIGN_LOGの内容と実装との差分を確認する。
2. `AGENTS.md`「ダイジェストと detail doc のアンカー同期ルール」に従い、アンカー ID・ポインタの対応関係を崩さないよう更新する
3. `README.md` へ反映する（必要時のみ。`CLAUDE.md`「ドキュメント言語方針」節の通り README.md は英語のみで統一する。反映不要な変更の場合はこのステップをスキップする）
4. 反映確認
5. 反映が完了したトピックの見出しのみ `DESIGN_LOG.md` から削除する。他の未反映トピックが残っている場合は、それらを巻き込んで削除しない（トピック単位の部分クリア）
6. 依存関係の最終確認（必要な場合のみ）

## DESIGN_LOG.md クリア漏れの機械的確認

新しいセッションでこの工程に着手する前に、まず `DESIGN_LOG.md` を開いて見出しが残っていないか確認する。見出しが残っている場合は、それが「反映済みだが削除し忘れているだけ」なのか「まだ未反映」なのかを、`CLAUDE.md`・対応する `docs/internal-design/*.md` の実際の記載と突き合わせて判定する。**反映済みと確認できた場合のみ削除する**。存在するというだけで自動的に削除してよいわけではない。

## 外部設計書はこの工程では更新しない

ドキュメント3層のうち、この工程で最新化するのは**内部設計書（`docs/internal-design/`）と `CLAUDE.md` のみ**である（層の定義は `CLAUDE.md`「ドキュメント構成（3層）」節を参照）。

外部設計書（`external-design/`）は 200_設計 工程で PO 承認を得て更新済みのはずであり、この工程では更新しない。**実装の結果として外部設計書の記述と実装が食い違っていることが判明した場合、この工程で勝手に書き換えず、200_設計 への差し戻しとしてMGへ報告する**（PO 承認済みの設計事項を、実装を追認する形で無断で書き換えないため）。

## OUTPUT

- 更新済み `CLAUDE.md` / `docs/internal-design/*.md`
- 更新済み `README.md`（該当時）
- 外部設計書との食い違いを検知した場合はその報告（この工程では修正しない）
