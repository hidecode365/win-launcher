## Windows 標準 API を優先する方針

**Windows 固有の機能を実装する際は、まず Windows 標準 API（Win32／WinRT／COM）で直接実装できないかを検討し、サードパーティクレートは標準 API での実装が著しく煩雑になる場合の代替手段として扱う。**

本プロジェクトは `ShellExecuteW`・`SHGetFileInfoW`・クリップボードの Win32 API 直接操作・OCR の WinRT 直呼び出し・`.lnk` 作成の `IShellLinkW`/`IPersistFile` 直接呼び出しなど、随所でこの方針を採っている。

この方針が実際に問題を回避した具体例として、`.lnk` 作成に使っていたサードパーティクレートに不具合が疑われた際、標準 API 直接呼び出しへ切り替えることで解決したケースがある。**Windows のファイルシステム／シェル関連の機能でサードパーティクレートに不具合が疑われた場合は、まずこの切り替えを検討すること。**

<a id="dialog-plugin-parent-window"></a>

## ダイアログ系プラグインは Rust 側のコマンドとして実装する

**新しいダイアログ・ポップアップ的な UI を Tauri プラグインで実装する場合、必ず Rust 側の Tauri コマンドとして実装し、親ウィンドウを明示的に指定すること。**

理由：本アプリのメインウィンドウは `alwaysOnTop: true` のため、親ウィンドウを指定しないダイアログはメインウィンドウの背後に回り込み、ユーザーからは「ダイアログが開かない」ように見える。フロントエンドの JS API には親ウィンドウを指定する手段がないものがあり、その場合は Rust 側での実装が必須になる。

現在フォルダ選択ダイアログがこの方針で実装されており、ダイアログ系の JS API をフロントエンドから直接呼ぶ経路は存在しない（npm 依存にも加えていない）。

<a id="paste-detection"></a>

## OS のクリップボードから実ファイルパスを読む方針

**OS のクリップボードから実ファイルパス（`CF_HDROP`）を読む必要が生じた場合、Rust 側で直接クリップボードを読み直す設計にする。**

理由：`CF_HDROP` はブラウザ／WebView2 の `clipboardData` に実ファイルパスとして現れない（`items`/`getData` 経由では取得できない）。フロントエンドのペーストイベントから取得しようとしても構造的に不可能であり、Rust 側で実クリップボードを開いて読み直す以外の方法がない。

<a id="heavy-data-ipc-policy"></a>

## 重量データを IPC に通さない方針

**クリップボード画像のような重量データは、フロントエンドへ渡さず Rust 側で処理を完結させる。**

具体的には、クリップボードの画像はバイナリを一度も IPC に通さない。Rust 側でクリップボードから直接読み、キャッシュに保持したうえで、フロントエンドへはキャッシュの ID とサムネイル（データURL）のみを通知する。書き戻しも ID を指定して Rust 側で行う。

理由：IPC 越しに大きなバイナリを転送すると、シリアライズ／デシリアライズのコストでフロントエンドの処理が重くなる。**今後、画像・大きなテキスト等の重量データを扱う機能を追加する場合も、同じく「実体は Rust 側に置き、識別子と表示用の軽量データだけを渡す」設計とすること。**

<a id="window-position-vs-size"></a>

## ウィンドウの位置は永続化せず、サイズのみ永続化する

**ウィンドウの表示位置は永続化せず、常に画面中央に表示する。一方、ウィンドウのサイズは永続化し、再起動後も最後に設定したサイズを維持する。**

この非対称な扱いは**意図的な仕様であり、矛盾ではない**。位置はランチャーとして「常に同じ場所（中央）に出る」ことの予測可能性を優先し、サイズはユーザーが自分の使い方に合わせて調整した結果を保持することを優先する。

ウィンドウを表示するすべての経路（グローバルホットキー／トレイ）で、表示直前に中央寄せを行う。

<a id="implicit-mode-coexistence"></a>

## 暗黙判定モードは共存させ、表示順序を固定する

数式計算・URLエンコード/デコードのような「入力内容から暗黙に判定されるモード」は、**ファイル検索結果と排他にせず共存させる**。計算結果はファイル検索結果を置き換えず、その先頭の別枠固定表示領域に表示する。

**表示順序をルールとして固定する**：計算結果 → URL変換結果 → ファイル検索結果の順とする。

現在の判定条件（数式は数字・演算子・括弧のみ、URL変換は `http(s)://` 始まり）は許容文字クラスが構造上排他のため、両者が同時に成立することはない。**しかし将来どちらかの判定条件が緩んで同時に成立しうるようになった場合に備え、この表示順序をルールとして維持すること。**

各モードの共存・排他関係の一覧は [01-screen-transitions.md の表1](01-screen-transitions.md#mode-coexistence-table) を参照。

<a id="prefix-command-extension-point"></a>

## 「/」プレフィックス機能の拡張ポイント

検索クエリが `/` から始まる場合、登録済みの全プレフィックスコマンドを候補一覧として表示する。

**新しい "/" プレフィックス機能を追加する場合、候補生成ロジックに1つ追加するだけで、既存の表示・選択・frecency の仕組みにそのまま乗る設計とする。個別の候補表示 UI を新設しない。**

- 候補は frecency スコアの降順で並び替える。この frecency はファイル検索結果と同じ仕組みを、キーだけ「ファイルパス」から「呼び出しキーワード」に変えて再利用する
- 呼び出しキーワードは互いに重複できない。**新しいキーワード設定を追加した場合は、必ず既存の重複チェックの対象リストに追加すること**
- 対応する機能が設定で OFF になっている場合、そのコマンドは候補生成の対象から除外する

<a id="settings-persistence-policy"></a>

## 永続化は単一のストアに集約する

**アプリのあらゆる永続データは `tauri-plugin-store` の `settings.json` 1ファイルに集約する。** 機能ごとに別ファイル・別の永続化機構（独自の設定ファイル、レジストリ、LocalStorage 等）を新設しない。

理由：保存先が分散すると、バックアップ・移行・不整合調査の対象が増え、「どの設定がどこに保存されているか」を都度調べる必要が生じる。単一ファイルであれば設定の実体を1箇所で確認でき、ユーザーが設定を丸ごと退避・復元することもできる。

**読み書きの経路は2種類あり、機能ごとにどちらかを選ぶ**：

| 経路 | 使いどころ |
| --- | --- |
| Rust コマンド経由 | 型の後方互換性を Rust 側の型定義で保証したいデータ（検索フォルダ・各機能の設定値・お気に入りのツリー等） |
| フロントエンドから JS の store API で直接 | Rust 側の型定義を持つ必要がなく、頻繁に書き込まれるデータ（frecency 履歴・ウィンドウサイズ・クリップボード履歴等） |

> **設定項目（フィールド）の一覧は本書には置かない。** フィールド一覧はコードから読み取れる派生情報であり、本書に転記すると設定を1つ追加するたびに PO レビューが発生し、かつコード側だけが更新されて本書が古くなる同期漏れの温床になるため。現在のフィールド一覧は [settings-panel-architecture.md#settings-persistence-schema](../internal-design/settings-panel-architecture.md#settings-persistence-schema) を参照。

<a id="dev-support-features"></a>

## 開発補助機能

製品機能ではなく、開発・調整作業を補助するための一時的な機能。**恒久機能ではないため、役目を終えた時点で削除する。**

### アイコン実測サイズのデバッグオーバーレイ

- **操作**：Ctrl+Alt+M でトグルする。Esc で閉じる
- **内容**：行内アイコンの共通ラッパー（`IconSlot`）の実測サイズを画面内に表示する開発者向けオーバーレイ
- **実装上の位置づけ**：window レベル `keydown` リスナーの**最優先分岐**として実装されており、該当時は以降の分岐を一切実行せず `return` する
- **導入理由**：DevTools はウィンドウのフォーカスアウト時自動非表示と競合して使えないため、実測値をアプリ内に直接表示する必要があった
- **削除予定（PO 決定）**：恒久機能ではなく、アイコン意匠の調整用の一時的な機能である。**段階5（`/memo`）の実装が完了し、アイコン配置が確定した時点で削除する。**
